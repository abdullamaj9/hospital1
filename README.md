# إيجنت واتساب الذكي - مستشفى الموسي التخصصي

نظام إيجنت ذكاء اصطناعي يعمل على واتساب (عبر UltraMsg)، يقوم بالحجز، التعديل، الإلغاء، التحقق من التوفر، وتحويل المحادثة لموظف الاستقبال تلقائياً عند الحاجة.

---

## 🚀 النشر على Render (يعمل 24/7 من GitHub)

### 1. رفع الكود إلى GitHub

```bash
cd almousa-whatsapp-agent
git init
git add .
git commit -m "إيجنت واتساب - مستشفى الموسي"
git branch -M main
git remote add origin https://github.com/USERNAME/almousa-whatsapp-agent.git
git push -u origin main
```

### 2. ربط المستودع بـ Render

1. اذهب إلى [render.com](https://render.com) وسجّل دخول (يمكنك تسجيل الدخول بحساب GitHub مباشرة).
2. اضغط **New** → **Web Service**.
3. اختر المستودع `almousa-whatsapp-agent` من GitHub.
4. Render سيكتشف ملف `render.yaml` تلقائياً ويعبّئ الإعدادات (Build Command: `npm install`, Start Command: `npm start`).
5. أضف متغير البيئة `ULTRAMSG_TOKEN` بقيمة `lh5al0k003eku9xf` (هذا الحقل محدد كـ "secret" في render.yaml فيطلب منك إدخاله يدوياً).
6. اضغط **Create Web Service**.

### 3. الحصول على رابط السيرفر

بعد انتهاء النشر (دقيقة أو دقيقتين)، سيعطيك Render رابطاً عاماً دائماً مثل:
```
https://almousa-whatsapp-agent.onrender.com
```

### 4. ربط الـ Webhook في UltraMsg

في لوحة UltraMsg → Instance → Webhooks → فعّل "Webhook on receive message" وضع:
```
https://almousa-whatsapp-agent.onrender.com/webhook
```

✅ بهذا لن تحتاج إطلاقاً لتشغيل جهازك أو cloudflared — السيرفر يعمل دائماً على Render.

## ⚠️ ملاحظات مهمة عن خطة Render المجانية

1. **القرص غير دائم (Ephemeral Disk)**: ملفات `data/*.json` (الحجوزات، المحادثات، التحويلات) **تُحذف عند كل إعادة نشر (deploy) أو إعادة تشغيل للسيرفر**. هذا مقبول للتجربة، لكن للاستخدام الفعلي يجب الانتقال لقاعدة بيانات خارجية (مثل خطة Render Disk المدفوعة، أو قاعدة بيانات مجانية مثل Supabase/MongoDB Atlas).

2. **سكون الخدمة (Sleep)**: في الخطة المجانية، يدخل السيرفر في وضع "نائم" بعد 15 دقيقة من عدم الاستخدام، وعند وصول أول رسالة واتساب يستغرق ~30-60 ثانية للاستيقاظ — قد يتأخر رد الإيجنت في أول رسالة بعد فترة خمول.

3. لتفادي السكون، يمكنك (اختياري) إعداد "ping" دوري كل 10 دقائق على رابط `/` باستخدام خدمة مجانية مثل UptimeRobot أو cron-job.org.

## المتطلبات
- Node.js (الإصدار 18 أو أحدث)
- حساب UltraMsg مفعّل ومتصل بواتساب
- cloudflared (لتعريض السيرفر المحلي على رابط عام)

## 1. التثبيت

```bash
cd almousa-whatsapp-agent
npm install
```

## 2. الإعدادات (اختياري - القيم الافتراضية موجودة في الكود)

يمكنك تجاوز القيم الافتراضية عبر متغيرات البيئة:

```bash
export ULTRAMSG_INSTANCE_ID=instance179001
export ULTRAMSG_TOKEN=lh5al0k003eku9xf
export RECEPTION_PHONE=971509788772   # رقم موظف الاستقبال (دولي بدون +)
export PORT=3300
```

## 3. تشغيل السيرفر

```bash
npm start
```

سيعمل السيرفر على: `http://localhost:3300`
ويستقبل رسائل واتساب على: `http://localhost:3300/webhook`

## 4. تعريض السيرفر عبر cloudflared (مطلوب لربط UltraMsg)

في نافذة طرفية أخرى:

```bash
cloudflared tunnel --url http://localhost:3300
```

سيعطيك رابطاً عاماً مثل:
```
https://xxxxx-xxxx-xxxx.trycloudflare.com
```

## 5. ربط الـ Webhook في UltraMsg

1. افتح لوحة UltraMsg → Instance → Webhooks
2. فعّل "Webhook on receive message" واضبط الرابط:
   ```
   https://xxxxx-xxxx-xxxx.trycloudflare.com/webhook
   ```
3. تأكد من تفعيل "Webhook on message received" فقط (لتجنب استقبال إشعارات غير ضرورية)

## 6. الاختبار

أرسل رسالة واتساب إلى رقم المستشفى المرتبط بـ UltraMsg (`0566350025` كما في مشروع كارلي، أو الرقم الذي ربطته فعلياً)، مثل:

```
السلام عليكم
```

سيرد الإيجنت بالقائمة الرئيسية.

## ميزات الإيجنت

| الميزة | الوصف |
|---|---|
| 1️⃣ حجز موعد | يسأل عن القسم، الطبيب، التاريخ، الوقت، بيانات المريض، ثم يؤكد الحجز |
| 2️⃣ استعلام عن الأقسام/الأطباء | يعرض القائمة الكاملة مع الأسعار ومدة الموعد |
| 3️⃣ مواعيد العمل | يعرض ساعات العمل ومعلومات الطوارئ |
| 4️⃣ العنوان والموقع | يرسل العنوان النصي + الموقع الجغرافي (Location pin) |
| 5️⃣ تعديل موعد | يعرض حجوزات العميل (بحسب رقم هاتفه) ويتيح تغيير التاريخ/الوقت |
| 6️⃣ إلغاء موعد | يعرض حجوزات العميل ويلغي المحدد |
| 🔍 التحقق من التوفر | يعرض الأوقات المتاحة لطبيب معين في تاريخ معين بدون حجز |
| 7️⃣ تحويل لموظف استقبال | عند الطلب المباشر، أو بعد محاولتين فاشلتين لفهم الطلب |

## منع تعارض المواعيد

النظام يتحقق تلقائياً أن نفس الطبيب لا يُحجز في نفس التاريخ والوقت من قبل أكثر من مريض (فحص عند كل خطوة + فحص نهائي عند التأكيد).

## التحويل لموظف الاستقبال

عند التحويل:
1. تُسجَّل المحادثة في `data/handoffs.json`
2. يُرسَل إشعار واتساب فوري لموظف الاستقبال (`RECEPTION_PHONE`) يحتوي على رقم العميل وسبب التحويل وآخر رسالة
3. يتوقف الإيجنت عن الرد التلقائي على هذا العميل حتى يكتب العميل "القائمة" مرة أخرى، أو يستخدم الموظف نقطة النهاية:
   ```
   POST /api/handoffs/{phone}/resolve
   ```

## نقاط النهاية المساعدة (API)

| المسار | الوصف |
|---|---|
| `GET /` | فحص صحة السيرفر |
| `GET /api/bookings` | عرض جميع الحجوزات (JSON) |
| `GET /api/handoffs` | عرض سجل التحويلات لموظف الاستقبال |
| `GET /api/conversations` | عرض حالة جميع المحادثات (لأغراض التصحيح) |
| `POST /api/handoffs/:phone/resolve` | إعادة تفعيل الإيجنت لعميل معين بعد تحويله |

## التخزين

جميع البيانات تُحفظ كملفات JSON في مجلد `data/`:
- `bookings.json` - الحجوزات (نفس صيغة حجوزات الموقع، يمكن استيرادها إلى لوحة admin.html)
- `conversations.json` - حالة كل محادثة (لتذكر مكان المستخدم في سير الحوار)
- `handoffs.json` - سجل التحويلات لموظف الاستقبال

> ملاحظة: بيانات الأقسام والأطباء (`data.js`) مطابقة لبيانات `data.js` في موقع المستشفى. عند تعديل أي طبيب أو قسم، يُفضّل تحديث الملفين معاً للحفاظ على التطابق.

## ملاحظات مهمة

- هذا نظام **تجريبي** يستخدم بيانات وهمية بالكامل (الأطباء، الأسعار، إلخ) كما في موقع المستشفى المرفق سابقاً.
- التخزين بصيغة JSON مناسب للتجربة والاستخدام الفردي. للانتقال لبيئة إنتاج حقيقية يُفضّل الانتقال لقاعدة بيانات (مثل SQLite أو PostgreSQL) لتفادي مشاكل الكتابة المتزامنة (race conditions) عند ازدحام الرسائل.
- يجب إبقاء السيرفر و cloudflared يعملان باستمرار لاستقبال الرسائل؛ إذا توقف أحدهما، سيتوقف الإيجنت عن الرد.
